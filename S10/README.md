# S10 — An honest, observable PyTorch training loop

This is the local PyTorch version of the assignment notebook. From the repository root:

```bash
python3 S10/run_demo.py
```

The same experiment is available as [`S10/S10_demo.ipynb`](S10_demo.ipynb). It runs the
script top-to-bottom and leaves generated evidence under `S10/artifacts/`.

## What the run checks

The tiny model trains on four real English sentences. Every tensor shape is printed with
the meaning of each dimension. The causal shift is shown as token strings, so the run
prints the input sequence beside its `t+1` targets rather than hiding the check in ids.

The finite-difference check perturbs `embedding.weight[2,0]` by ±0.001 and compares the
central difference with `backward()`. A mismatch above `1e-3` fails the recorded check.

Gradient accumulation is intentionally broken once: unequal micro-batches use an average
of their averages. The correct path weights each micro-loss by its contributing-token
count. Both curves are generated in
[`artifacts/accumulation_curves.png`](artifacts/accumulation_curves.png), and every row is
in `evidence.json`.

The normal training loop records loss and gradient norm at every step. It reports the
adjacent step with the largest gradient-norm movement relative to loss movement, making a
“gradient moved before the loss” event inspectable rather than anecdotal.

MFU is estimated as `6 × parameters × training_tokens / elapsed / assumed_peak_FLOP/s`.
The run uses an explicitly conservative one-core CPU peak assumption of `1e9 FLOP/s`.
This is an honest diagnostic estimate: it omits kernel-specific FLOPs and is not a GPU or
vendor benchmark. The README reports the distance to 40% and the likely causes—small
matrices, Python/framework overhead, memory traffic and the conservative peak denominator.

For 0.1, the generated evidence records:

| Format | Bits | Hex | Represented value |
|---|---|---|---:|
| FP32 | `0 01111011 10011001100110011001101` | `0x3dcccccd` | 0.10000000149 |
| BF16 | `0 01111011 1001101` | `0x3dcd` | 0.10009765625 |
| FP8 E4M3FN | `0 0011 101` | `0x1d` | 0.1015625 |

The recommended training choice is BF16 activations on hardware with reliable BF16
kernels, with FP32 master weights and optimizer accumulation. FP8 E4M3 needs calibrated
scaling/loss handling and is not chosen blindly for this loop.

## Generated evidence

- [`run.log`](artifacts/run.log): shapes, string shift, gradient check, accumulation, norms and MFU.
- [`evidence.json`](artifacts/evidence.json): machine-readable measurements and bit fields.
- [`grad_trace.json`](artifacts/grad_trace.json): per-step loss and gradient norm.
- [`accumulation_curves.png`](artifacts/accumulation_curves.png): broken versus correct curves.

All artifacts are regenerated by the command; no measured result is used as a runtime
constant. Tests are in `S10/tests/test_s10.py`.
