# S12 — A 32-virtual-rank ZeRO simulation

Run the complete demo:

```bash
python3 S12/run_demo.py
```

The run creates a real PyTorch model and training loop, then computes transparent
ZeRO-0/ZeRO-1/ZeRO-2/ZeRO-3 state-placement and communication accounting for 32 virtual
GPU ranks. The virtual ranks are CPU-side accounting units; this is not a claim that one
CPU process has reproduced NCCL latency or real multi-GPU overlap.

## The demo model

`DemoModel` is a small four-layer MLP with 128-dimensional input/output and width 256. It
has a real forward pass, MSE loss, backward pass, and three AdamW updates on a fixed batch
of 32 examples. Its parameter count and loss trace are generated in `evidence.json` and
the event log. The same mathematical compute is assigned to each virtual rank; ZeRO changes
where parameters, gradients, and Adam state live.

## What each ZeRO stage means

The simulation uses FP32 parameters (4 bytes), FP32 gradients (4 bytes), and Adam first and
second moments (8 bytes total): 16 unsharded state bytes per parameter.

| Stage | Parameters per rank | Gradients per rank | Adam state per rank | Main saving |
|---|---|---|---|---|
| ZeRO-0 | replicated | replicated | replicated | baseline |
| ZeRO-1 | replicated | replicated | sharded over 32 | optimizer state |
| ZeRO-2 | replicated | sharded over 32 | sharded over 32 | optimizer + gradients |
| ZeRO-3 | sharded over 32 | sharded over 32 | sharded over 32 | all model state |

The generated records report per-rank bytes/MiB, reduction versus ZeRO-0, shard factors,
estimated ring communication per step, and the same arithmetic FLOPs for all stages. ZeRO
does not magically reduce the mathematical forward/backward work; its central benefit is
per-rank memory capacity, traded for collectives.

## Communication model

The communication numbers use a stated ring-style volume approximation with factor
`(world_size-1)/world_size`:

- ZeRO-0: 0 additional state-collective bytes in this accounting.
- ZeRO-1: gradient synchronization.
- ZeRO-2: gradient reduce-scatter plus parameter synchronization.
- ZeRO-3: parameter all-gather for computation plus gradient reduce-scatter.

These are bandwidth-volume estimates, not measured wall-clock latency. A real distributed
benchmark would need NCCL, topology, overlap, bucket sizes, and network measurements.

## Generated evidence

- [`run.log`](artifacts/run.log) records the 32 virtual ranks, real model run, and every stage.
- [`evidence.json`](artifacts/evidence.json) contains all formulas, assumptions, memory,

- [`zero_comparison.png`](artifacts/zero_comparison.png) compares per-rank state memory and

All values are regenerated by `run_demo.py`; no stage result is hard-coded in the artifact.
